Le « temps réel », c'est ce qui fait qu'un message, une coche bleue ou une puce verte apparaissent sans recharger la page. Il repose sur plusieurs fichiers qui travaillent ensemble. On commence par le principe, puis on suit chaque fichier.

1. Le principe : SSE, Transmit et canaux

Normalement, le web fonctionne ainsi : le navigateur demande, le serveur répond. Le serveur ne peut jamais parler le premier. Pour qu'un message arrive tout seul, il faut une connexion qui reste ouverte.

Ton projet utilise Transmit, le module temps réel d'AdonisJS, qui repose sur les SSE (Server-Sent Events) :

  1. à l'ouverture d'une page, le navigateur ouvre une connexion vers /__transmit/events ;
  2. le serveur ne la ferme pas : elle reste ouverte tant que la page est affichée ;
  3. dès que le serveur a quelque chose à dire, il l'écrit dans cette connexion, et le navigateur le reçoit immédiatement.

Les données circulent sur des canaux, comme des stations de radio. Un navigateur s'abonne aux canaux qui l'intéressent, et ne reçoit que ce qui y est diffusé. Ton application en utilise deux sortes :

CanalQui l'écouteCe qui y passe
users/<id sans tirets>Seulement son propriétaireSes nouveaux messages, modifications, coches bleues, ajouts à un groupe...
presenceToutes les personnes connectées« Untel vient de passer en ligne / hors ligne »

SSE ou WebSocket ? Les SSE ne vont que dans un sens : du serveur vers le navigateur. C'est suffisant ici, car pour parler au serveur (envoyer un message, signaler une lecture), le navigateur utilise de simples requêtes fetch.

Dans start/routes.ts, Transmit ajoute ses routes, protégées par l'authentification :

// Transmit ajoute 3 routes (/__transmit/events, subscribe, unsubscribe).
transmit.registerRoutes((route) => {
  route.middleware(middleware.auth())
})

registerRoutes crée trois routes : ouvrir la connexion (events), s'abonner à un canal (subscribe) et se désabonner (unsubscribe). Le callback ajoute le middleware auth à chacune : sans être connecté, impossible d'ouvrir la connexion.

Et dans config/transmit.ts :

export default defineConfig({
  pingInterval: '30s',
  transport: null,
})
  • pingInterval: '30s' : toutes les 30 secondes, le serveur envoie un petit « ping » dans chaque connexion. Sans ça, certains proxys ou hébergeurs couperaient une connexion qui semble inactive.
  • transport: null : aucun relais entre plusieurs serveurs (comme Redis). Les événements ne circulent qu'à l'intérieur d'un seul processus serveur (voir les remarques).

2. start/transmit.ts : qui écoute quoi, qui est en ligne

Ce fichier est chargé au démarrage du serveur. Il fait trois choses : protéger les canaux, suivre qui est en ligne, et remettre tout le monde hors ligne au démarrage.

import db from '@adonisjs/lucid/services/db'
import logger from '@adonisjs/core/services/logger'
import transmit from '@adonisjs/transmit/services/main'
import { PRESENCE_CHANNEL, annoncePresence, convertitEnIdentifiantCanal } from '../app/service/realtime_service.ts'

db pour mettre à jour la colonne is_online, logger pour noter les erreurs, transmit pour le temps réel, et trois outils de realtime_service.ts (expliqués au point 3).

Partie 1 : qui a le droit de s'abonner à quel canal ?

transmit.authorize<{ id: string }>('users/:id', (ctx, { id }) => {
  const currentUser = ctx.auth.user
  return currentUser !== undefined && convertitEnIdentifiantCanal(currentUser.id) === id
})
  • transmit.authorize(motif, règle) : appelée à chaque demande d'abonnement à un canal qui correspond au motif. Si la règle renvoie false, l'abonnement est refusé.
  • 'users/:id' : comme une route, :id capture la partie variable du nom. Pour users/3f2a9c1e..., id vaut '3f2a9c1e...'.
  • <{ id: string }> : dit à TypeScript que les paramètres contiennent un id texte.
  • La règle : il faut être connecté et que l'id du canal soit le tien (sans tirets). C'est la protection essentielle : sans elle, n'importe qui pourrait écouter le canal d'un autre et lire ses messages en direct.
transmit.authorize(PRESENCE_CHANNEL, (ctx) => {
  return ctx.auth.user !== undefined
})

Le canal presence est ouvert à toute personne connectée.

Partie 2 : suivre qui est en ligne

Règle choisie : un utilisateur est « en ligne » tant qu'au moins une de ses pages est ouverte, donc tant qu'il a au moins une connexion Transmit. Trois dictionnaires (Map) gardent cet état en mémoire :

// uid de la connexion → identifiant de l'utilisateur
const connectionOwners = new Map<string, string>()

// identifiant de l'utilisateur → nombre de connexions ouvertes (un onglet = une connexion)
const connectionCounts = new Map<string, number>()

// identifiant de l'utilisateur → minuteur avant de le passer "hors ligne"
const offlineTimers = new Map<string, NodeJS.Timeout>()
DictionnaireExemplePourquoi
connectionOwners'abc-uid' → 'user-5'À la fermeture, Transmit ne donne que l'uid de la connexion : il faut retrouver à qui elle appartenait.
connectionCounts'user-5' → 2Avec deux onglets, fermer l'un ne doit pas te passer hors ligne.
offlineTimers'user-5' → minuteurPour annuler le passage hors ligne si tu reviens vite.
const OFFLINE_DELAY_MS = 8000

Quand tu changes de page, l'ancienne connexion se ferme et la nouvelle s'ouvre une fraction de seconde après. Sans délai, ta puce clignoterait (hors ligne, puis en ligne) à chaque clic. On attend donc 8 secondes avant de déclarer quelqu'un hors ligne.

async function changeStatutEnLigne(userId: string, isOnline: boolean) {
  try {
    await db.from('users').where('id', userId).update({ is_online: isOnline })
    annoncePresence(userId, isOnline) // tout le monde est prévenu
  } catch (error) {
    logger.error({ err: error, userId }, 'Échec de la mise à jour du statut en ligne')
  }
}

Change le statut en deux temps : en base (pour que les pages chargées ensuite affichent le bon état) puis en direct sur le canal presence (pour les pages déjà ouvertes). En cas d'erreur, on note dans les logs sans faire planter le serveur.

Une connexion s'ouvre

transmit.on('connect', async ({ uid, context }) => {
  const userId = context.auth.user?.id
  if (!userId) {
    return
  }

  connectionOwners.set(uid, userId)

transmit.on('connect', ...) est appelée à chaque nouvelle connexion (page ouverte). On retrouve l'utilisateur, puis on note que cette connexion lui appartient.

  const pendingTimer = offlineTimers.get(userId)
  const wasOnline = (connectionCounts.get(userId) ?? 0) > 0 || pendingTimer !== undefined

  connectionCounts.set(userId, (connectionCounts.get(userId) ?? 0) + 1)
  • wasOnline : il était déjà considéré en ligne s'il avait déjà une connexion, ou si un minuteur « hors ligne » était en attente (il vient juste de changer de page).
  • On ajoute 1 à son nombre de connexions. Le ?? 0 gère le cas où il n'en avait aucune.
  if (pendingTimer !== undefined) {
    clearTimeout(pendingTimer)
    offlineTimers.delete(userId)
  }

  if (!wasOnline) {
    await changeStatutEnLigne(userId, true)
  }
})

S'il est revenu avant la fin des 8 secondes, on annule le passage hors ligne. Et on n'annonce « en ligne » que s'il ne l'était pas déjà : inutile de prévenir tout le monde à chaque changement de page.

Une connexion se ferme

transmit.on('disconnect', ({ uid }) => {
  const userId = connectionOwners.get(uid)
  if (!userId) {
    return
  }
  connectionOwners.delete(uid)

  const remaining = (connectionCounts.get(userId) ?? 1) - 1

  if (remaining > 0) {
    connectionCounts.set(userId, remaining)
    return
  }

On retrouve le propriétaire grâce à l'uid, on oublie cette connexion, puis on retire 1 à son compteur. S'il lui reste d'autres onglets, il reste en ligne et on s'arrête là.

  connectionCounts.delete(userId)
  offlineTimers.set(
    userId,
    setTimeout(async () => {
      offlineTimers.delete(userId)
      await changeStatutEnLigne(userId, false)
    }, OFFLINE_DELAY_MS)
  )
})

C'était sa dernière connexion : on programme son passage hors ligne dans 8 secondes, et on garde le minuteur pour pouvoir l'annuler s'il revient (voir connect).

Partie 3 : au démarrage du serveur

try {
  await db.from('users').update({ is_online: false })
} catch (error) {
  logger.warn({ err: error }, 'Impossible de réinitialiser les statuts en ligne au démarrage')
}

Si le serveur s'est arrêté brutalement, des utilisateurs sont restés is_online = true en base, alors que plus personne n'est connecté. Au démarrage, on remet donc tout le monde hors ligne. Ils repasseront en ligne en rouvrant une page.

3. realtime_service.ts : envoyer les événements

Le commentaire en tête résume le principe, toujours le même :

  1. le contrôleur enregistre d'abord en base de données ;
  2. il appelle une fonction previens... de ce fichier ;
  3. l'événement part sur le canal personnel de chaque destinataire ;
  4. dans le navigateur, realtime.js le reçoit et message.js met la page à jour.

Et un choix important : le HTML est fabriqué ici, côté serveur, avec les mêmes vues Edge qu'au chargement de la page.

Les imports

import edge from 'edge.js'
import db from '@adonisjs/lucid/services/db'
import logger from '@adonisjs/core/services/logger'
import transmit from '@adonisjs/transmit/services/main'
import type Conversation from '#models/conversation'
import type Message from '#models/message'
import type User from '#models/user'
import type UserConversation from '#models/user_conversation'
import { construitVueMessage, construitApercu, donneInitiales, donneHeureDeLaListe,
         estPremierMessageVisible, besoinSeparateurDeJour } from './chat_service.ts'
  • edge : le moteur de vues, utilisé directement. Dans un contrôleur on a view (lié à la requête) ; ici on fabrique du HTML pour d'autres personnes que celle qui a fait la requête, donc on utilise edge sans contexte.
  • Les modèles : importés avec type, car ils ne servent qu'à décrire les paramètres.
  • Les outils de chat_service.ts : les mêmes qu'au chargement de la page, pour que tout s'affiche à l'identique.
export const PRESENCE_CHANNEL = 'presence'
export type ConversationKind = 'private' | 'group'

Le nom du canal de présence, partagé avec start/transmit.ts pour ne pas l'écrire deux fois, et le type « privée ou groupe ».

Les canaux

export function convertitEnIdentifiantCanal(userId: string): string {
  return userId.replaceAll('-', '')
}

export function donneCanalUtilisateur(userId: string): string {
  return `users/${convertitEnIdentifiantCanal(userId)}`
}

Un nom de canal ne peut contenir que des lettres, des chiffres et /. Tes identifiants sont des uuid avec des tirets : on les retire. Exemple : 3f2a9c1e-7b4d-... donne le canal users/3f2a9c1e7b4d.... Le navigateur applique exactement la même règle dans realtime.js.

function envoieAUtilisateur(
  userId: string,
  event: NonNullable<Parameters<typeof transmit.broadcast>[1]>
) {
  try {
    transmit.broadcast(donneCanalUtilisateur(userId), event)
  } catch (error) {
    logger.error({ err: error, userId }, "Échec de l'envoi d'un événement temps réel")
  }
}
  • transmit.broadcast(canal, données) : envoie les données à tous les navigateurs abonnés à ce canal. Pour un canal personnel, ce sont tous les onglets de cet utilisateur.
  • Le type de event : se lit de l'intérieur vers l'extérieur. typeof transmit.broadcast = le type de la fonction ; Parameters<...> = la liste de ses paramètres ; [1] = le deuxième (les données) ; NonNullable = sans null ni undefined. Bref : « exactement ce que broadcast accepte », sans le recopier.
  • Le try/catch : un problème de temps réel ne doit jamais faire échouer l'action de l'utilisateur. Le message est déjà enregistré en base ; au pire, l'autre le verra en rechargeant.
  • Pas d'export : seules les fonctions de ce fichier l'utilisent.

Présence

export function annoncePresence(userId: string, isOnline: boolean) {
  try {

  } catch (error) {

Diffuse sur le canal commun presence : tout le monde apprend que userId est en ligne ou non. Appelée par changeStatutEnLigne dans start/transmit.ts.

Une boucle sur chaque destinataire, avec un try/catch par destinataire : si la préparation échoue pour l'un, les autres sont quand même prévenus.

Lecture des messages : marqueConversationCommeLueEtPrevient

Appelée quand quelqu'un ouvre une conversation, ou reçoit un message alors qu'il la regarde.

export async function marqueConversationCommeLueEtPrevient(userId: string, conversationId: number) {
  const unreadRows = await db
    .from('message_statuses')
    .where('user_id', userId)
    .where('is_read', false)
    .whereIn('message_id', db.from('messages').select('id').where('conversation_id', conversationId))
    .select('message_id')

  if (unreadRows.length === 0) {
    return
  }

  const messageIds = unreadRows.map((row) => row.message_id as number)

1. On cherche tes statuts non lus pour les messages de cette conversation (la sous-requête donne la liste des messages de la conversation). S'il n'y en a aucun, on s'arrête : pas de requête inutile. Sinon, on garde la liste de leurs identifiants. as number indique à TypeScript le type de la colonne, car db.from renvoie des lignes sans type précis.

  await db
    .from('message_statuses')
    .where('user_id', userId)
    .whereIn('message_id', messageIds)
    .update({ is_read: true, status: 'read', updated_at: new Date() })

2. On les passe à « lu », en une seule requête UPDATE.

  const fullyReadMessages = await db
    .from('messages')
    .whereIn('id', messageIds)
    .whereNotExists((query) => {
      query
        .from('message_statuses')
        .whereRaw('message_statuses.message_id = messages.id')
        .where('message_statuses.is_read', false)
    })
    .select('id', 'user_id')

3. Parmi ces messages, lesquels sont maintenant lus par tous leurs destinataires ? whereNotExists garde les messages pour lesquels il n'existe plus aucun statut non lu. whereRaw('message_statuses.message_id = messages.id') relie la sous-requête au message en cours d'examen. En privé, il n'y a qu'un destinataire, donc tous passent. Dans un groupe, la coche ne devient bleue que quand tout le monde a lu.

  const idsByAuthor = new Map<string, number[]>()
  for (const row of fullyReadMessages) {
    const authorId = row.user_id as string
    idsByAuthor.set(authorId, [...(idsByAuthor.get(authorId) ?? []), row.id as number])
  }

4. On regroupe les messages par auteur. Pour chaque ligne, on reprend la liste déjà connue de cet auteur (ou une liste vide), on y ajoute l'identifiant avec [...ancienne, nouveau], et on la range. Résultat par exemple : { 'ana' → [41, 42], 'jo' → [43] }.

  for (const [authorId, ids] of idsByAuthor) {
    envoieAUtilisateur(authorId, { type: 'messages:read', conversationId, messageIds: ids })
  }
}

5. Chaque auteur reçoit un seul événement avec la liste de ses messages lus, et ses coches passent au bleu. for (const [clé, valeur] of map) parcourt une Map en décomposant chaque paire.

L'outil afficheLigneListe

function afficheLigneListe(item: Record<string, unknown>, isGroup: boolean): Promise<string> {
  return edge.render('partials/list-item', {
    item,
    chatUrl: isGroup ? '/groups' : '/conversations',
    isGroup,
    canDelete: !isGroup,
  })
}

Fabrique le HTML d'une ligne de la liste, avec le même partial list-item qu'au chargement. Record<string, unknown> = « un objet avec des clés texte et des valeurs de n'importe quel type ». chatUrl donne le début du lien de la ligne, et canDelete n'autorise le bouton supprimer que pour une conversation privée. La fonction n'a pas de async : elle renvoie directement la promesse de edge.render, que l'appelant attend avec await.

    .join('messages', 'messages.id', 'message_statuses.message_id')

    .join('conversation_types', 'conversation_types.id', 'conversations.conversation_type_id')
    .where('message_statuses.user_id', user.id)
    .where('message_statuses.is_read', false)
    .where('messages.is_deleted', false)
    .select('conversation_types.type')
    .count('* as total')
    .groupBy('conversation_types.type')

On part de tes statuts non lus et on remonte, avec trois jointures : statut → message → conversation → type de conversation. On exclut les messages supprimés. groupBy sur le type donne un total par type, en une seule requête. Résultat par exemple :

1. Connexion au serveur

const transmit = new Transmit({
  baseUrl: window.location.origin,

  uidGenerator: function () {
    if (window.crypto && window.crypto.randomUUID) {
      return window.crypto.randomUUID()
    }
    return Date.now().toString(36) + Math.random().toString(36).slice(2)
  },

  beforeSubscribe: function (requete) {
    requete.headers.set('X-CSRF-TOKEN', jetonCsrf)
  },

  onSubscribeFailed: function (reponse) {
    console.error("Abonnement au temps réel refusé (code " + reponse.status + ")")
  },
})
  • baseUrl : l'adresse du serveur, ici celle de la page (par exemple https://monsite.com).
  • uidGenerator : fabrique l'identifiant unique de cette connexion (c'est le uid reçu par connect et disconnect côté serveur). crypto.randomUUID() n'existe que sur une page sécurisée (HTTPS ou localhost) : sur un téléphone testé via une adresse IP en HTTP, on utilise une solution de secours (date + nombre aléatoire en base 36).
  • beforeSubscribe : ajoute le jeton CSRF avant chaque abonnement.
  • onSubscribeFailed : si le serveur refuse l'abonnement (par exemple un 403 de transmit.authorize), on l'écrit dans la console.
let dejaConnecte = false

9. Ce qui a été remarqué

Un seul serveur à la fois : la présence est suivie dans des Map en mémoire, et transport: null ne relie pas plusieurs processus. Si l'application tournait un jour sur deux instances, un message envoyé sur l'une n'atteindrait pas les connexions ouvertes sur l'autre, et les statuts en ligne seraient faux. Il faudrait alors un transport comme Redis. Avec une seule instance, comme actuellement, tout fonctionne.

Redémarrage du serveur : au démarrage, tout le monde passe hors ligne. Les navigateurs encore ouverts se reconnectent automatiquement et repassent en ligne, mais kc:reconnecte rechargera alors aussi les pages Messages et Groupes.

Événements perdus pendant une coupure : les SSE de Transmit ne rejouent pas les événements manqués. C'est pour ça que la page se recharge après une reconnexion ; les autres pages ne rafraîchissent que les pastilles.

La présence est visible par tous : toute personne connectée reçoit les changements de statut de tout le monde sur le canal presence, même de personnes avec qui elle n'a jamais parlé. C'est cohérent avec la page Utilisateurs, qui les affiche déjà.

Identifiant non numérique : comme ailleurs, Number(params.id) dans marqueCommeLu peut donner NaN, avec probablement une erreur 500 au lieu d'une 404.
