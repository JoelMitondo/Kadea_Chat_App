Les vues Edge de Kadea Chat expliquées

Dossier resources/views/ · layouts · components · partials · pages · emails

Les vues fabriquent le HTML envoyé au navigateur. Kadea Chat utilise Edge, le moteur de vues d'AdonisJS : du HTML normal, avec des balises spéciales pour afficher des données, faire des conditions et réutiliser des morceaux. Les classes CSS (Tailwind) sont volontairement laissées de côté dans les extraits : elles ne servent qu'au style. Ce qui compte ici, c'est la structure.

Le principe de tout le dossier : écrire chaque morceau une seule fois. Une bulle de message est écrite dans un fichier (message-bubble.edge). Le même fichier sert au chargement de la page, à l'envoi, au temps réel et aux « messages précédents ». C'est pour ça qu'une bulle a toujours exactement le même aspect, d'où qu'elle vienne.

1. La syntaxe d'Edge en 10 points

SyntaxeRôleExemple dans le projet
{{ valeur }}Affiche une valeur échappée : < devient &lt;, donc un texte ne peut jamais devenir du HTML actif{{ message.content }}
{{{ valeur }}}Affiche sans échappement. À réserver au HTML qu'on a fabriqué soi-même{{{ await $slots.main() }}}
{{-- ... --}}Un commentaire, jamais envoyé au navigateurPartout
@if / @elseif / @else / @endUne condition@if(chat.blockedByMe)
@each(x in liste)Une boucle. @each((x, index) in liste) donne aussi la position@each(item in conversations)
@let(nom = valeur)Une variable locale à la vue@let(message = $props.get('message'))
@include('partials/x')Insère un autre fichier, qui voit les mêmes variables@include('partials/chat-panel')
@component('components/x', { ... }) … @endInsère un composant avec ses propres données (props), et un contenu entre les deux balises (le slot)@component('components/stat-card', {...}) + une icône
@!component(...)Le même, sans contenu : le ! veut dire « pas de @end »@!component('components/message-bubble', { message })
@layouts.app({ ... }) … @endUn raccourci pour le composant components/layouts/app.edge. Le point remplace le /En tête de chaque page
  • $props.get('nom', défaut) : dans un composant, lit une donnée reçue, avec une valeur par défaut facultative. $props.has('nom') teste si elle a été passée.
  • $slots.main() : le contenu placé entre @component(...) et @end. C'est une fonction asynchrone, d'où le await. On l'affiche avec {{{ }}}, car c'est du HTML écrit par nous.
  • Les variables disponibles partout, ajoutées par AdonisJS : auth (l'utilisateur connecté), csrfToken, csrfField(), cspNonce, route('nom', params), flashMessages, old('champ')…
  • include ou component ? Un @include partage toutes les variables de la vue qui l'inclut, ce qui est pratique pour découper une grande page. Un @component ne reçoit que ses props : il est réutilisable n'importe où, comme une fonction.

3. Le layout app.edge (pages connectées)

Le <head>

<title>{{ $props.get('title', 'Kadea Chat') }}</title>
<meta name="description" content="Kadea Chat : Application web de chat">
<meta property="og:title" content="Kadea Chat | Application web de conversation">
<meta property="og:image" content="https://i.ibb.co/zVsVm0NQ/Screenshot-17.png">
<meta property="twitter:card" content="summary_large_image">
<meta name="theme-color" content="#2563eb">
<link rel="icon" href="https://i.ibb.co/1YhrGKHz/logo-Kadea.png" type="image/png">
<meta name="csrf-token" content="{{ csrfToken }}">
@include('partials/head-script')
@vite(['resources/css/compiles/app.css'])
@vite(['resources/js/realtime.js'])
  • Le titre vient de la page : @layouts.app({ title: 'Messages · Kadea Chat' }), ou « Kadea Chat » par défaut.
  • Les balises og: et twitter: (Open Graph) décident de l'aperçu affiché quand on partage le lien sur WhatsApp, Facebook ou LinkedIn : titre, description, image. theme-color colore la barre du navigateur sur téléphone.
  • <meta name="csrf-token"> : le jeton CSRF, lu par realtime.js pour ses requêtes (voir le fichier sur le socle).
  • @include('partials/head-script') : le petit script avec le nonce de la CSP, qui applique le thème clair ou sombre avant l'affichage (pas de flash blanc) et gère les images cassées.
  • @vite([...]) ajoute la balise <link> ou <script type="module"> du fichier. En développement, elle pointe vers le serveur Vite. En production, vers le fichier compilé avec son nom à empreinte (app-3f2a.css), pour le cache.
  • realtime.js est chargé dans le <head>, sur toutes les pages connectées : la connexion temps réel s'ouvre partout, pour les pastilles et les notifications.

Le <body>

<body data-user-id="{{ auth.user.id }}">
  @!component('components/loader')
  @!component('components/toasts')

  <header>

    <form action="/search" method="GET"><input type="search" name="q" placeholder="Rechercher un message…"></form>
    <a href="/search">loupe (téléphone)</a>

    <form action="/logout" method="POST">{{ csrfField() }}<button type="submit">…</button></form>
  </header>

  <nav aria-label="Navigation principale">
    @component('components/nav-item', { href: '/messages', label: 'Messages', active: $props.get('active') === 'messages', delay: 100, badge: 'private' })
      <svg>…</svg>
    @end
    … Groupes (badge: 'group'), Utilisateurs, Mon profil …
  </nav>

  <main>
    {{{ await $slots.main() }}}
  </main>

  @vite(['resources/js/compiles/animate.js'])
</body>
  • data-user-id : l'identifiant de l'utilisateur connecté, lu par realtime.js pour s'abonner à son canal personnel. Le layout app n'est utilisé que sur des routes protégées par auth, donc auth.user existe toujours.
  • Le chargeur et la zone des notifications sont posés une fois, en haut de chaque page.
  • L'en-tête :
    • la barre de recherche est un vrai formulaire GET /search, qui fonctionne sans JavaScript ;
    • sur téléphone, une simple loupe vers /search la remplace ;
    • la déconnexion est un formulaire POST avec csrfField(). Le commentaire précise que c'est plus sûr qu'un lien : un lien piégé ne peut pas déconnecter.
  • La navigation : chaque bouton est un composant nav-item. L'icône SVG est passée dans le slot. active compare le active reçu de la page (@layouts.app({ active: 'messages' })) pour mettre le bon bouton en évidence. Le commentaire explique la mise en page : barre en bas sur téléphone, à gauche sur ordinateur, qui s'agrandit au survol par-dessus le contenu sans le pousser.
  • {{{ await $slots.main() }}} : c'est ici que s'insère le contenu propre à chaque page.
  • animate.js à la fin : les notifications, le chargeur et le bouton de thème (voir le fichier sur le JavaScript principal).

Le composant nav-item

<a href="{{ $props.get('href') }}"
   aria-current="{{ $props.get('active') ? 'page' : 'false' }}"
   style="animation-delay: {{ $props.get('delay', 0) }}ms">
  <span>
    {{{ await $slots.main() }}}
    @if($props.get('badge'))
      <span data-nav-badge="{{ $props.get('badge') }}">0</span>
    @end
  </span>
  <span>{{ $props.get('label') }}</span>
</a>
  • aria-current="page" dit aux lecteurs d'écran « c'est la page actuelle ». Le CSS s'en sert aussi pour colorer le bouton.
  • animation-delay : les boutons apparaissent l'un après l'autre (100, 200, 300, 400 ms), pour un petit effet de cascade.
  • La pastille data-nav-badge (private ou group) est créée à 0 et cachée. realtime.js la remplit avec le nombre de messages non lus, reçu de /unread-counts.

4. Les layouts auth.edge et landing.edge

  • auth.edge (connexion, inscription, mot de passe oublié) : le même <head>, mais sans realtime.js, puisque personne n'est connecté. L'en-tête est réduit au logo (lien vers l'accueil) et au bouton de thème. Le contenu est centré, avec un pied de page « © 2026 Kadea Chat · Projet chef-d'œuvre Kadea Academy ». En fin de page, il charge compiles/auth.js (la vérification en direct de l'inscription) et animate.js.
  • landing.edge (page d'accueil) : un en-tête avec des liens d'ancre vers les sections (#fonctionnalites, #comment-ca-marche), le bouton de thème, et des boutons qui changent selon isLoggedIn : « Mes messages » ou « Se connecter / S'inscrire ».
{{-- pages/home.edge --}}
@let(isLoggedIn = auth.isAuthenticated)

@layouts.landing({ title: 'Kadea Chat · Discutez simplement, en privé ou en groupe', isLoggedIn: isLoggedIn })
  ...
  @if(isLoggedIn)
    <a href="/messages">…</a>
  @else
    <a href="{{ route('inscriptions.create') }}">…</a> <a href="/login">…</a>
  @end
  • auth.isAuthenticated est déjà connu, sans aucune requête du navigateur. Le middleware silent_auth a vérifié la session avant d'afficher la page (voir le fichier sur le socle). La route / n'a même pas de contrôleur : router.on('/').render('pages/home').
  • La page passe isLoggedIn au layout comme une prop, pour adapter les boutons de l'en-tête.
  • Le reste de l'accueil est de la présentation : un aperçu de discussion dessiné en HTML, les cartes de fonctionnalités (feature-card), une explication en étapes, et un appel à l'action final.

5. Les composants de la messagerie

user-avatar.edge : l'avatar, avec la présence en direct

@let(sizeClasses = $props.get('size') === 'sm' ? 'h-10 w-10' : 'h-12 w-12')
@let(toneClasses = $props.get('tone') === 'group' ? 'bg-group-soft text-group' : 'bg-primary-soft text-on-primary-soft')
@let(isOnline = Boolean($props.get('online')))
@let(showOffline = Boolean($props.get('showOffline')))

<span data-presence-user="{{ $props.get('userId', '') }}"
      data-show-offline="{{ showOffline ? 'true' : 'false' }}">
  <span>{{ $props.get('initials') }}</span>
  @if($props.get('src'))
    <img src="{{ $props.get('src') }}" alt="" data-remove-on-error>
  @end
  <span data-presence-online title="En ligne">…</span>
  <span data-presence-offline title="Hors ligne"></span>
</span>
  • Des props pour toutes les situations :
    • la taille (size: 'sm') ;
    • la couleur pour un groupe (tone: 'group') ;
    • la puce verte (online), et la puce grise « hors ligne » seulement si on la demande (showOffline) ;
    • userId, pour le temps réel.
  • Les initiales sont toujours là, la photo par-dessus. Si la photo ne se charge plus (supprimée de Cloudinary), data-remove-on-error la retire, et les initiales réapparaissent.
  • data-presence-user : realtime.js retrouve tous les avatars d'une personne grâce à cet attribut, et allume ou éteint sa puce quand l'événement presence arrive. Les deux puces sont toujours dans le HTML, et une seule est visible.
  • Boolean(...) transforme undefined (prop non passée) en false.

    @else

    @end

  • Une seule ligne pour les conversations privées et les groupes : isGroup choisit l'avatar (photo et présence, ou initiales colorées), et canDelete affiche la corbeille, seulement en privé.

  • Il est utilisé trois fois : dans la liste de message.edge et groups.edge, et par partials/list-item.edge, la ligne envoyée par le temps réel quand une nouvelle conversation apparaît.

message-bubble.edge : une bulle

@let(message = $props.get('message'))
@let(bubbleClasses = message.isMine
  ? 'rounded-br-md bg-bubble-out text-on-bubble-out'
  : 'rounded-bl-md border border-bubble-line bg-bubble-in text-on-bubble-in')

<div data-message-id="{{ message.id }}">
  @if(message.isMine && !message.isDeleted)
    @if(!message.attachment)
      <button type="button" data-edit-message>crayon</button>
    @end
    <button type="button" data-delete-message>corbeille</button>
  @end

  @if(message.senderName)
    <p>{{ message.senderName }}</p>
  @end

  @if(message.isDeleted)
    <p>Ce message a été supprimé</p>
  @else
    @if(message.attachment)
      @if(message.attachment.isImage)
        <a href="{{ message.attachment.url }}" target="_blank" rel="noopener">
          <img src="{{ message.attachment.thumbUrl }}" alt="{{ message.attachment.name }}" loading="lazy">
        </a>
      @else
        <p>{{ message.attachment.name }}</p>
      @end
      <span>{{ message.attachment.size }}</span> · <a href="{{ message.attachment.url }}" target="_blank" rel="noopener">Ouvrir</a>
      · <a href="{{ message.attachment.downloadUrl }}">Télécharger</a>
    @end
    @if(message.content)
      <p data-message-text>{{ message.content }}</p>
    @end
  @end

  @if(message.isEdited && !message.isDeleted) <span>modifié</span> @end
  <span>{{ message.time }}</span>
  @if(message.isMine && !message.isDeleted)
    <span data-tick-read aria-label="Lu">…</span>
    <span data-tick-delivered aria-label="Reçu">…</span>
    <span data-tick-sent aria-label="Envoyé">…</span>
  @end
</div>

Toutes les données viennent de construitVueMessage (voir le fichier sur les services) : la vue n'a aucun calcul à faire, seulement des conditions.

  • bubbleClasses : mes messages à droite en bleu, ceux des autres à gauche avec une bordure. Le coin « en pointe » est du côté de l'auteur.
  • Les boutons Modifier / Supprimer n'apparaissent que sur mes messages non supprimés. Un message avec un fichier ne peut être que supprimé. C'est de l'affichage : le serveur revérifie avec la policy.
  • Le nom de l'auteur n'apparaît que dans un groupe, et pas sur mes propres messages (senderName vaut alors null).
  • Une image s'affiche en miniature (thumbUrl, 480 px, format optimisé). Un clic ouvre l'original dans un nouvel onglet.
    • rel="noopener" empêche la page ouverte de prendre le contrôle de l'onglet d'origine (window.opener).
    • loading="lazy" ne charge l'image qu'au moment où elle approche de l'écran, ce qui allège les longues discussions.
  • « Télécharger » pointe vers downloadUrl (fl_attachment), qui force l'enregistrement du fichier.
  • data-message-text : message.js y lit le texte à mettre dans le champ quand on clique sur « Modifier ».
  • Les trois coches sont toujours présentes sur mes messages, et une seule est visible. La classe hidden dépend de isRead et isDelivered : par exemple, la coche « Reçu » est visible si !message.isRead && message.isDelivered. Le temps réel bascule ensuite de l'une à l'autre (afficherCoche).
  • {{ message.content }} est échappé : un message <script>alert(1)</script> s'affiche comme du texte. C'est la protection principale contre les attaques XSS, et la CSP en est la seconde.

@each((message, index) in messages)

    @!component('components/day-separator', { label: message.dayLabel })
  @end

{{-- day-separator.edge --}}
<div data-day-separator><span>{{ $props.get('label') }}</span></div>
  • Un séparateur de jour (« Aujourd'hui », « Hier », « Lundi »…) avant le premier message, puis à chaque fois que dayKey ("2026-11-06") change par rapport au message précédent.

@if($props.get('hasMore'))

composer.edge : la zone de saisie

<form id="composer" action="{{ $props.get('action') }}" method="POST" data-no-loader>
  <div id="edit-banner">Modification du message <button type="button" data-cancel-edit>✕</button></div>
  <div id="attachment-chip"><span id="attachment-name"></span> <button type="button" data-remove-attachment>✕</button></div>

  <input id="attachment-input" type="file" accept=".jpg,.jpeg,.png,.gif,.webp,.pdf,.doc,.docx,.xls,.xlsx,.ppt,.pptx,.txt,.csv">
  <button type="button" data-pick-attachment>trombone</button>
  <input name="content" type="text" autocomplete="off" maxlength="2000" placeholder="{{ $props.get('placeholder', 'Écrire un message…') }}">
  <button type="submit" aria-label="Envoyer">avion en papier</button>
</form>
  • Une seule zone de saisie pour le privé et les groupes : seule l'adresse d'envoi (action) et le texte d'invitation changent.
  • Le bandeau de modification et l'étiquette du fichier sont dans le HTML, cachés. message.js les montre quand il faut.
  • Le vrai champ de fichier est caché, car un <input type="file"> est difficile à styler. Le joli trombone appelle .click() dessus. accept limite les types proposés dans la fenêtre de choix du système.

  • Pas de csrfField() : ce formulaire n'est jamais envoyé normalement. message.js envoie lui-même le jeton dans l'en-tête X-CSRF-TOKEN.

6. Les autres composants

Les cartes à icône : stat-card, info-row, feature-card

{{-- stat-card.edge --}}
@let(tones = { primary: 'bg-primary-soft …', group: 'bg-group-soft …', accent: 'bg-accent-soft …' })
<div>
  <span class="{{ tones[$props.get('tone')] }} …">{{{ await $slots.main() }}}</span>
  <p>{{ $props.get('value') }}</p>
  <p>{{ $props.get('label') }}</p>

{{-- utilisation dans pages/profile.edge --}}
@component('components/stat-card', { label: 'Groupes', value: stats.groups, tone: 'group' })
  <svg>…</svg>
@end
  • Le même modèle pour les trois : les textes passent par les props, et l'icône passe par le slot (le SVG entre @component et @end).
  • tones : un petit dictionnaire qui associe un nom de couleur à des classes. La page écrit tone: 'group' sans connaître les classes Tailwind.
  • info-row utilise <dt> / <dd>, les balises HTML d'une liste « intitulé : valeur ». Les lecteurs d'écran annoncent ainsi chaque paire correctement.

toasts.edge et loader.edge

  • toasts.edge contient :
    • la zone #kc-toasts (aria-live="polite") où s'empilent les notifications ;
    • le <template id="kc-toast-modele"> que notifications.js copie ;
    • les messages flash du serveur, écrits en <div data-flash="succes" data-message="…" hidden> quand flashMessages.has('success') (ou 'error').
  • loader.edge : un anneau SVG avec un filtre « liquide » (feGaussianBlur pour flouter, puis feColorMatrix pour durcir les contours, ce qui fait fusionner les gouttes avec l'anneau), le logo au centre et « Veuillez patienter ! ». Il est visible par défaut, et un <noscript> le cache si JavaScript est désactivé.

Les composants de formulaire : form, field/*, input/control, link

Ils viennent du kit de démarrage d'AdonisJS et servent surtout à la page de connexion et à l'inscription.

{{-- utilisation (pages/auth/login.edge) --}}
@form({ route: 'session.store', method: 'POST' })
  @field.root({ name: 'email' })
    @!field.label({ text: 'Adresse e-mail' })
    @!input.control({ type: 'email', autocomplete: 'username' })
    @!field.error()
  @end
@end
  • form/index.edge transforme route: 'session.store' en action et method (formAttributes), puis ajoute tout seul {{ csrfField() }} si la méthode n'est pas GET.
  • field/root.edge prépare un « contexte » partagé avec ses enfants grâce à @inject({...}) :
    • le nom et l'id du champ ;
    • l'ancienne valeur (old('email'), pour garder ce qui a été tapé après une erreur) ;
    • les erreurs du champ, lues dans le flash inputErrorsBag.
  • field/label, input/control et field/error lisent ce contexte avec $context. Le label reçoit for, le champ reçoit name, id, value et aria-invalid, et l'erreur s'affiche sous le champ. On écrit name: 'email' une seule fois, et les trois morceaux sont reliés.
  • input/control ne remet jamais l'ancienne valeur pour un mot de passe ou un fichier (useOldValue). Un mot de passe ne doit pas revenir pré-rempli dans la page.
  • $props.except([...]).merge({...}).toAttrs() : on prend toutes les props, on retire celles qui ne sont pas des attributs HTML, on ajoute les siennes, puis on transforme le tout en attributs. Toute prop non prévue (placeholder, autocomplete…) passe donc directement sur la balise.
  • link.edge fabrique un <a> à partir d'un nom de route (urlFor) ou d'un href.

10. Qui rend quelle vue

view.render('pages/xxx')             → une page complète (contrôleur, requête normale)
view.render('partials/xxx')          → un morceau (contrôleur, requête du JavaScript)
edge.render('partials/xxx')          → un morceau pour UN AUTRE utilisateur (realtime_service)
this.message.htmlView('emails/xxx')  → le contenu d'un e-mail (app/mails)
  • view est lié à la requête : il connaît auth, csrfToken, les messages flash… C'est lui qu'utilisent les contrôleurs.
  • edge est le moteur seul, sans requête. realtime_service.ts l'utilise pour fabriquer la bulle que verra le destinataire, alors que la requête en cours est celle de l'expéditeur. C'est pour ça que message-item et list-item n'utilisent que les données qu'on leur passe, jamais auth.

11. Ce qui a été remarqué

Ce qui est bien fait, à mettre en avant :

• Chaque morceau est écrit une seule fois (bulle, ligne de liste, avatar, zone de saisie), et réutilisé partout, y compris par le temps réel.

• Deux pages, un seul JavaScript, grâce aux mêmes identifiants et aux adresses rangées dans data-….

• {{ }} partout pour les données : {{{ }}} n'est utilisé que pour les slots et le HTML écrit par nous.

• Des vues sans calcul : tout est préparé par construitVueMessage et les contrôleurs.

• Des liens et formulaires qui marchent sans JavaScript (recherche, liens de conversation, déconnexion), améliorés quand JavaScript est là.

• L'accessibilité : aria-label sur les boutons à icône, aria-current, <dt>/<dd>, role="status" sur le chargeur.

1. Les balises de partage et l'icône sont recopiées dans les trois layouts (une vingtaine de lignes identiques dans app, auth et landing). Une modification doit être faite trois fois. On pourrait les ranger dans un partials/head-meta.edge, comme head-script.edge.

2. L'adresse du site est écrite en dur dans og:url et twitter:url (https://agora-chat-app-1.onrender.com/), et le logo, l'icône et l'image de partage sont hébergés sur i.ibb.co. Si l'adresse change ou si ce service supprime les images, les aperçus et le logo seront cassés. Mieux vaut mettre ces images dans public/ et utiliser publicUrl de config/app.ts. La CSP pourrait alors retirer https://i.ibb.co.

3. Dans la liste des membres d'un groupe, la présence ne se met pas à jour en direct. Les avatars de group-panel.edge reçoivent online mais pas userId. realtime.js ne peut donc pas les retrouver, et la puce reste celle du chargement. Il suffit d'ajouter userId: member.id.

4. « 1 membres » : après des retraits, un groupe peut n'avoir plus qu'un ou deux membres, et l'en-tête écrit toujours « membres » au pluriel. Un petit @if(chat.group.membersCount > 1) réglerait le cas.

5. Des commentaires dépassés : errors/error.edge cite encore app/service/error_page.ts (au lieu de app/services). groups.edge dit « messages.js d'abord : groups.js utilise ses fonctions », alors que la page ne charge que groupe.js, qui importe message.js. L'indentation de la fin de chat-panel.edge est aussi décalée.

6. field/label.edge affiche son texte avec {{{ }}}, sans échappement. C'est sans danger aujourd'hui, car tous les textes de label sont écrits par nous dans les vues. Mais il ne faudrait jamais y passer une donnée venant d'un utilisateur.
