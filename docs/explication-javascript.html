Le JavaScript principal expliqué ligne par ligne

resources/js/message.js (parties 1 à 7) · notifications.js · loader.js · compiles/animate.js

Ces trois fichiers font vivre l'interface sans recharger la page :

  • message.js : toute la messagerie (ouvrir une discussion, envoyer, modifier, supprimer, joindre un fichier, le bouton Retour du téléphone) ;
  • notifications.js : les petites notifications en haut à droite et l'envoi des formulaires data-ajax ;
  • loader.js : le chargeur plein écran.

La partie 8 de message.js (le temps réel) est déjà expliquée dans le fichier sur le temps réel, et groupe.js dans celui sur les groupes.

Trois idées reviennent partout :

• Le serveur fabrique le HTML (bulles, panneaux, lignes de liste), et le JavaScript se contente de l'insérer. Une bulle a donc toujours le même aspect, qu'elle vienne du chargement de la page, de l'envoi ou du temps réel.

• La délégation d'événements : un seul écouteur sur le document gère tous les boutons, même ceux ajoutés plus tard.

• Les attributs data-… relient le HTML et le JavaScript (data-message-id, data-edit-message, data-ajax…). Le JavaScript ne dépend jamais des classes CSS, qui servent seulement au style.

1. Comment et dans quel ordre les fichiers sont chargés

FichierChargé parSur quelles pages
realtime.js@vite dans le <head> de layouts/app.edgeToutes les pages connectées
message.js@vite dans pages/message.edge, et importé par groupe.jsMessages et Groupes
compiles/animate.js, qui importe notifications.js, loader.js et theme.js@vite à la fin des trois layoutsToutes
  • Des « modules » : Vite charge ces fichiers avec <script type="module">. Un module :
    • s'exécute après la lecture complète du HTML (comme defer), donc tous les éléments de la page existent déjà ;
    • s'exécute dans l'ordre d'apparition dans la page : realtime.js, puis message.js, puis animate.js ;
    • n'est exécuté qu'une fois, même s'il est importé plusieurs fois.
  • export / import : message.js exporte envoyer et lireErreur, et groupe.js fait import { envoyer, lireErreur } from './message.js'. Sur la page Groupes, importer message.js l'exécute aussi : la page Groupes réutilise toute la messagerie (ouvrir, envoyer…). groupe.js n'ajoute que la gestion des groupes.
  • window.kcNotifier et window.kcLoader : pour être appelables depuis n'importe quel fichier sans import, ces deux objets sont rangés sur window. Ils sont créés par animate.js, donc après message.js. Ce n'est pas un problème : message.js ne les appelle qu'au moment d'un clic ou d'une réponse, quand tout est chargé.

  • On récupère une fois pour toutes les éléments principaux de la page.
  • jeton : le jeton CSRF, lu dans un champ caché de la page. Il sera envoyé avec chaque requête qui modifie quelque chose.
  • Les deux adresses viennent du HTML (data-list-url, data-chat-url). C'est l'astuce qui permet au même fichier de servir la page Messages (/conversations/12) et la page Groupes (/groups/12) : seules ces deux valeurs changent.

envoyer : une requête JSON au serveur

export async function envoyer(adresse, methode, donnees) {
  let options = {
    method: methode,
    headers: { Accept: 'application/json', 'X-CSRF-TOKEN': jeton },
  }

  if (donnees !== undefined) {
    options.headers['Content-Type'] = 'application/json'
    options.body = JSON.stringify(donnees)
  }

  try {
    let reponse = await fetch(adresse, options)
    let corps = {}
    try {
      corps = await reponse.json()
    } catch (erreurLecture) {
      corps = {}
    }
    return { ok: reponse.ok, corps: corps }
  } catch (erreurReseau) {
    return { ok: false, corps: { message: 'Impossible de contacter le serveur. Vérifiez votre connexion.' } }
  }
}
  • Les en-têtes :
    • Accept: application/json demande une réponse JSON. Le handler du serveur répond alors toujours en JSON, même en cas d'erreur (voir le fichier sur le socle).
    • X-CSRF-TOKEN porte le jeton de sécurité.
  • Avec des données : JSON.stringify les transforme en texte JSON, et Content-Type annonce ce format au serveur.
  • Deux try imbriqués :
    • celui de l'extérieur attrape une panne réseau : fetch ne lance une erreur que si le serveur n'a pas pu être joint ;
    • celui de l'intérieur attrape une réponse qui n'est pas du JSON (réponse vide, page d'erreur HTML).
  • Attention : une réponse 404 ou 500 ne fait pas échouer fetch. Il faut regarder reponse.ok, qui vaut vrai pour un code entre 200 et 299.
  • Elle renvoie toujours { ok, corps } et ne lance jamais d'erreur. Les appelants n'ont qu'à tester resultat.ok.
export function lireErreur(corps) {
  if (corps.errors && corps.errors.length > 0 && corps.errors[0].message) {
    return corps.errors[0].message
  }
  return corps.message || 'Une erreur est survenue. Veuillez réessayer.'
}

function defilerEnBas() {
  let zone = document.getElementById('messages-list')
  if (zone !== null) {
    zone.scrollTop = zone.scrollHeight
  }
}
  • lireErreur trouve le message d'erreur quelle que soit sa forme : errors[0].message (validation, ou format unifié du handler) ou message, avec un texte par défaut. C'est la contrepartie du format unique choisi côté serveur.
  • defilerEnBas : scrollHeight est la hauteur totale du contenu. En mettant scrollTop à cette valeur, on descend tout en bas, sur le dernier message.

3. message.js : la liste des conversations

function marquerActive(id) {
  let elements = liste.querySelectorAll('[data-conversation-item]')

  elements.forEach(function (element) {
    let estActive = id !== null && element.dataset.conversationId === String(id)
    element.dataset.active = estActive ? 'true' : 'false'

    if (estActive) {
      element.querySelector('[data-unread-badge]').classList.add('hidden')
    }
  })

  page.dataset.activeId = id === null ? '' : String(id)
}
  • Met en surbrillance la conversation ouverte : le CSS colore la ligne qui a data-active="true".
  • String(id) : les attributs data-… sont toujours du texte. On compare donc du texte avec du texte, car '12' === 12 vaut false.
  • La pastille de non-lus disparaît pour la conversation ouverte : ses messages viennent d'être lus.
  • page.dataset.activeId retient quelle conversation est ouverte. Le temps réel s'en sert pour savoir s'il faut ajouter une bulle ou augmenter une pastille.
function mettreAJourListe(idConversation, apercu, heure) {
  let element = liste.querySelector('[data-conversation-item][data-conversation-id="' + idConversation + '"]')
  if (element === null) { return }

  element.querySelector('[data-preview]').textContent = apercu
  element.querySelector('[data-time]').textContent = heure
  liste.prepend(element)
}

function verifierListeVide() {
  let aucuneConversation = liste.querySelectorAll('[data-conversation-item]').length === 0
  listeVide.classList.toggle('hidden', !aucuneConversation)
}
  • mettreAJourListe change l'aperçu et l'heure, puis remonte la conversation en haut. prepend d'un élément déjà présent le déplace, sans le copier.
  • Deux sélecteurs collés ([data-conversation-item][data-conversation-id="12"]) veulent dire « un élément qui a les deux attributs à la fois ».
  • textContent insère du texte, jamais du HTML : un aperçu piégé ne peut rien exécuter.
  • verifierListeVide affiche « Aucune conversation » quand la dernière disparaît. classList.toggle('hidden', condition) ajoute la classe si la condition est vraie, et la retire sinon.

4. message.js : ouvrir et fermer une discussion

async function ouvrirConversation(id) {
  let reponse
  try {
    reponse = await fetch(adresseChat + '/' + id, { headers: { 'X-Requested-With': 'XMLHttpRequest' } })
  } catch (erreurReseau) {
    kcNotifier.erreur('Impossible de contacter le serveur. Vérifiez votre connexion.')
    return false
  }

  if (!reponse.ok) {
    kcNotifier.erreur(messageErreurOuverture(reponse.status))
    if (reponse.status === 401) {
      setTimeout(function () { window.location.href = '/login' }, 2000)
    }
    return false
  }

  panneau.innerHTML = await reponse.text()
  fichierJoint = null
  marquerActive(id)
  page.dataset.view = 'chat'
  defilerEnBas()

  document.dispatchEvent(new CustomEvent('kc:rafraichir-compteurs'))
  return true
}
  • X-Requested-With: XMLHttpRequest dit au contrôleur « c'est le JavaScript ». Il renvoie alors seulement le panneau en HTML (partials/chat-panel ou group-panel), qu'on place avec innerHTML.
  • En cas d'erreur, un message adapté au code (messageErreurOuverture) :
    • 401 : la session a expiré, et on renvoie vers /login après 2 secondes, le temps de lire le message ;
    • 404 : la discussion n'existe plus ;
    • 500 et plus : problème du serveur.
  • fichierJoint = null : un fichier choisi dans l'ancienne conversation est oublié.
  • page.dataset.view = 'chat' : sur téléphone, le CSS cache la liste et montre la discussion en plein écran.
  • kc:rafraichir-compteurs : un événement maison. realtime.js l'écoute et met à jour les pastilles de la barre de navigation, puisque des messages viennent d'être lus. C'est une façon de faire parler deux fichiers sans qu'ils s'importent.
  • Elle renvoie true ou false : l'appelant ne met l'adresse à jour que si l'ouverture a réussi.
function fermerChat() {
  panneau.innerHTML = modeleAccueil.innerHTML
  page.dataset.view = 'list'
  marquerActive(null)
}

On remet le message d'accueil, copié depuis un <template id="chat-placeholder"> de la page. Sur téléphone, la liste réapparaît, et plus aucune conversation n'est en surbrillance.

5. message.js : le bouton Retour (historique)

Le problème, expliqué par le commentaire : la discussion s'ouvre sans changer de page. Pour le navigateur, on est toujours sur /messages. Sur téléphone, le bouton Retour quitterait l'application au lieu de revenir à la liste. Il faut donc ajouter soi-même une étape dans l'historique.

function memoriserDansHistorique(id) {
  let etat = { vue: 'chat', id: id }
  let adresse = adresseChat + '/' + id

  if (history.state !== null && history.state.vue === 'chat') {
    history.replaceState(etat, '', adresse)
  } else {
    history.pushState(etat, '', adresse)
  }
}
  • history.pushState(état, titre, adresse) ajoute une étape à l'historique et change l'adresse affichée (/conversations/12), sans recharger. L'état est un petit objet que le navigateur garde avec l'étape.
  • La règle, d'après le commentaire : l'historique contient toujours [liste, discussion]. Si une discussion est déjà ouverte et qu'on en ouvre une autre, on remplace l'étape (replaceState) au lieu d'en ajouter une. Un seul Retour ramène donc à la liste, et pas à chaque conversation visitée.
if (page.dataset.view === 'chat') {
  let idOuvert = page.dataset.activeId
  history.replaceState({ vue: 'liste' }, '', adresseListe)
  history.pushState({ vue: 'chat', id: idOuvert }, '', adresseChat + '/' + idOuvert)
  defilerEnBas()
} else {
  history.replaceState({ vue: 'liste' }, '', adresseListe)
}
  • Au chargement de la page, deux cas.
  • Page ouverte directement sur une discussion (lien /conversations/12, rechargement) : il n'y a pas d'étape « liste » avant. On la fabrique en remplaçant l'étape actuelle par la liste, puis on ajoute la discussion. Retour ramène alors à la liste, comme si on était passé par elle.
  • Page ouverte sur la liste : on marque simplement l'étape actuelle comme « liste ».
window.addEventListener('popstate', function (evenement) {
  let etat = evenement.state
  if (etat !== null && etat.vue === 'chat') {
    ouvrirConversation(etat.id)
  } else {
    fermerChat()
  }
})

popstate se déclenche quand on navigue dans l'historique (Retour, Suivant). evenement.state est l'objet enregistré avec l'étape. Si c'est une discussion, on la rouvre. Sinon, on ferme et on revient à la liste.

6. message.js : envoyer, joindre un fichier, modifier

Le fichier joint

let fichierJoint = null

const EXTENSIONS_ACCEPTEES = ['jpg', 'jpeg', 'png', 'gif', 'webp', 'pdf', 'doc', 'docx', 'xls', 'xlsx', 'ppt', 'pptx', 'txt', 'csv']
const TAILLE_MAX_FICHIER = 10 * 1024 * 1024 // 10 Mo

function choisirFichier(fichier) {
  let extension = fichier.name.split('.').pop().toLowerCase()

  if (EXTENSIONS_ACCEPTEES.indexOf(extension) === -1) {
    kcNotifier.erreur('Type de fichier non accepté. ...')
    retirerFichierJoint()
    return
  }
  if (fichier.size > TAILLE_MAX_FICHIER) {
    kcNotifier.erreur('Le fichier est trop lourd : 10 Mo maximum.')
    retirerFichierJoint()
    return
  }

  fichierJoint = fichier
  document.getElementById('attachment-name').textContent = fichier.name
  document.getElementById('attachment-chip').classList.remove('hidden')
  document.getElementById('attachment-chip').classList.add('flex')
}
  • fichierJoint garde en mémoire le fichier choisi avec le trombone, en attendant l'envoi.
  • Les mêmes listes que le validateur du serveur (IMAGE_EXTENSIONS, DOCUMENT_EXTENSIONS, 10 Mo). On refuse tout de suite plutôt qu'après un envoi de plusieurs Mo.
  • name.split('.').pop() : on découpe le nom aux points, et on prend le dernier morceau. rapport.final.PDF donne PDF, puis pdf après toLowerCase().
  • Si le fichier est accepté, une petite étiquette avec son nom s'affiche au-dessus du champ de saisie.
function retirerFichierJoint() {
  fichierJoint = null
  let champ = document.getElementById('attachment-input')
  let bandeau = document.getElementById('attachment-chip')
  if (champ !== null) { champ.value = '' }
  if (bandeau !== null) {
    bandeau.classList.add('hidden')
    bandeau.classList.remove('flex')
  }
}

Elle annule le fichier. champ.value = '' vide le champ de fichier : sans ça, choisir à nouveau le même fichier ne déclencherait pas l'événement change. Les tests !== null protègent quand aucune discussion n'est ouverte.

async function envoyerFichier(adresse, contenu, fichier) {
  let donnees = new FormData()
  donnees.append('content', contenu)
  donnees.append('attachment', fichier)

  let reponse = await fetch(adresse, {
    method: 'POST',
    headers: { Accept: 'application/json', 'X-CSRF-TOKEN': jeton },
    body: donnees,
  })
  ...
}
  • Pourquoi pas envoyer ? Le commentaire l'explique : le JSON ne sait transporter que du texte. Un fichier doit partir dans un FormData, un formulaire construit à la main, envoyé au format multipart/form-data.
  • Pas de Content-Type écrit à la main : avec un FormData, le navigateur le met lui-même, avec la « frontière » qui sépare les morceaux. L'écrire soi-même casserait l'envoi.
  • Les noms content et attachment sont exactement ceux qu'attend sendMessageValidator côté serveur.
document.addEventListener('change', function (evenement) {
  if (evenement.target.id !== 'attachment-input') { return }
  let fichier = evenement.target.files[0]
  if (fichier !== undefined) {
    choisirFichier(fichier)
  }
})

L'écouteur est posé sur le document, et non sur le champ de fichier. Ce champ est dans le panneau, remplacé à chaque ouverture de discussion (innerHTML). Un écouteur posé directement sur lui disparaîtrait au premier changement de conversation.

Le mode modification

function entrerModeEdition(idMessage) {
  let bulle = document.querySelector('[data-message-id="' + idMessage + '"]')
  let formulaire = document.getElementById('composer')
  if (bulle === null || formulaire === null) { return }

  let zoneTexte = bulle.querySelector('[data-message-text]')
  if (zoneTexte === null) { return }

  retirerFichierJoint()

  let champ = formulaire.querySelector('[name="content"]')
  champ.value = zoneTexte.textContent.trim()

  formulaire.dataset.editingId = idMessage
  document.getElementById('edit-banner').classList.remove('hidden')
  document.getElementById('edit-banner').classList.add('flex')
  champ.focus()
}

function quitterModeEdition() {
  let formulaire = document.getElementById('composer')
  if (formulaire === null) { return }
  delete formulaire.dataset.editingId
  formulaire.querySelector('[name="content"]').value = ''
  document.getElementById('edit-banner').classList.add('hidden')
  document.getElementById('edit-banner').classList.remove('flex')
}
  • Pas de champ séparé pour modifier : on réutilise le champ de saisie habituel. On y recopie le texte de la bulle, et on retient l'identifiant du message dans data-editing-id.
  • Un message sans texte (fichier seul) n'a pas de [data-message-text] et ne peut pas être modifié.
  • Un bandeau « Modification en cours » s'affiche, avec un bouton pour annuler.
  • delete formulaire.dataset.editingId retire l'attribut. C'est sa présence qui indique le mode modification.

L'envoi du formulaire

document.addEventListener('submit', async function (evenement) {
  let formulaire = evenement.target
  if (formulaire.id !== 'composer') { return }

  evenement.preventDefault()

  let champ = formulaire.querySelector('[name="content"]')
  let bouton = formulaire.querySelector('[type="submit"]')
  let contenu = champ.value.trim()
  let idEdition = formulaire.dataset.editingId

  if (contenu === '' && (idEdition || fichierJoint === null)) { return }

  let idConversation = document.getElementById('chat-panel').dataset.conversationId
  bouton.disabled = true

  let resultat
  if (idEdition) {
    resultat = await envoyer('/messages/' + idEdition, 'PUT', { content: contenu })
  } else if (fichierJoint !== null) {
    resultat = await envoyerFichier(formulaire.getAttribute('action'), contenu, fichierJoint)
  } else {
    resultat = await envoyer(formulaire.getAttribute('action'), 'POST', { content: contenu })
  }

  bouton.disabled = false
  • preventDefault() bloque l'envoi normal du formulaire, qui rechargerait la page.
  • Rien à envoyer ? En modification, il faut du texte. Sinon, il faut du texte ou un fichier. Lisez la condition : « texte vide et (en modification ou sans fichier) », alors on s'arrête.
  • Le bouton est désactivé pendant l'envoi, contre le double clic qui enverrait deux fois le message.
  • Trois chemins :
    • modification : PUT /messages/:id en JSON ;
    • avec fichier : FormData vers l'adresse du formulaire ;
    • texte seul : POST en JSON.
    L'adresse du formulaire (action) est écrite par la vue : /conversations/12/messages ou /groups/12/messages.
  if (!resultat.ok) {
    kcNotifier.erreur(lireErreur(resultat.corps))
    return
  }

  if (idEdition) {
    let ancienne = document.querySelector('[data-message-id="' + idEdition + '"]')
    ancienne.outerHTML = resultat.corps.html
    quitterModeEdition()
  } else {
    retirerMessageVide()
    document.getElementById('messages-list').insertAdjacentHTML('beforeend', resultat.corps.html)
    champ.value = ''
    retirerFichierJoint()
    defilerEnBas()
  }

  if (resultat.corps.isLast) {
    mettreAJourListe(idConversation, resultat.corps.preview, resultat.corps.time)
  }
  champ.focus()
})
  • En cas d'erreur (bloqué, fichier refusé, session expirée…), le message du serveur s'affiche. Le texte tapé reste dans le champ : rien n'est perdu.
  • Modification : outerHTML remplace toute l'ancienne bulle (l'élément lui-même, pas seulement son contenu) par la nouvelle, fabriquée par le serveur, avec la mention « modifié ».
  • Nouveau message :
    • on retire « Aucun message » s'il était affiché ;
    • on ajoute la bulle à la fin (insertAdjacentHTML('beforeend', …)). Le HTML reçu contient aussi le séparateur de jour si nécessaire ;
    • on vide le champ et le fichier, puis on descend en bas.
  • isLast : si c'est le dernier message de la conversation, l'aperçu de la liste change et la conversation remonte en haut.
  • champ.focus() : le curseur reste dans le champ, pour enchaîner un autre message.

7. message.js : supprimer, bloquer

async function supprimerMessage(idMessage) {
  if (!confirm('Supprimer ce message ?')) { return }

  let resultat = await envoyer('/messages/' + idMessage, 'DELETE')
  if (!resultat.ok) {
    kcNotifier.erreur(lireErreur(resultat.corps))
    return
  }

  let bulle = document.querySelector('[data-message-id="' + idMessage + '"]')
  bulle.outerHTML = resultat.corps.html
  quitterModeEdition()

  if (resultat.corps.isLast) {
    let idConversation = document.getElementById('chat-panel').dataset.conversationId
    mettreAJourListe(idConversation, resultat.corps.preview, resultat.corps.time)
  }
}
  • confirm(...) affiche une boîte « OK / Annuler » du navigateur, et renvoie true ou false.
  • La bulle n'est pas retirée, elle est remplacée par la version « Ce message a été supprimé » renvoyée par le serveur (suppression « douce »).
  • quitterModeEdition() : si on était en train de modifier ce message, le mode modification est annulé.
async function supprimerConversation(element) {
  let id = element.dataset.conversationId
  if (!confirm('Supprimer cette conversation ? Elle disparaîtra de votre liste.')) { return }

  let resultat = await envoyer(adresseChat + '/' + id, 'DELETE')
  if (!resultat.ok) { kcNotifier.erreur(lireErreur(resultat.corps)); return }

  let etaitOuverte = page.dataset.activeId === id
  element.remove()
  verifierListeVide()
  kcNotifier.succes(resultat.corps.message)

  if (etaitOuverte) {
    if (history.state !== null && history.state.vue === 'chat') {
      history.back()
    } else {
      fermerChat()
    }
  }
}
  • La ligne disparaît de la liste (côté serveur, c'est removedAt qui est rempli).
  • Si la conversation était ouverte, il faut la fermer proprement. Avec history.back(), on revient à l'étape « liste » de l'historique, et l'événement popstate appelle fermerChat(). Fermer directement laisserait une étape « discussion » dans l'historique : Retour rouvrirait une conversation supprimée.
async function changerBlocage(idUtilisateur, bloquer) {
  let question = bloquer
    ? 'Bloquer cet utilisateur ? Il ne pourra plus vous envoyer de nouveaux messages.'
    : 'Débloquer cet utilisateur ?'
  if (!confirm(question)) { return }

  let adresse = '/users/' + idUtilisateur + (bloquer ? '/block' : '/unblock')
  let resultat = await envoyer(adresse, 'POST')
  if (!resultat.ok) { kcNotifier.erreur(lireErreur(resultat.corps)); return }

  kcNotifier.succes(resultat.corps.message)
  ouvrirConversation(page.dataset.activeId)
}

Une seule fonction pour bloquer et débloquer : le paramètre bloquer choisit la question et l'adresse. Ensuite, on recharge le panneau, et le serveur renvoie le bandeau et le bon bouton (« Bloquer » ou « Débloquer »). Le JavaScript n'a pas à reconstruire l'affichage lui-même.

8. message.js : tous les clics, en un seul écouteur

document.addEventListener('click', async function (evenement) {
  let cible = evenement.target

  let lien = cible.closest('[data-conversation-link]')
  if (lien !== null) {
    evenement.preventDefault()
    let id = lien.dataset.conversationId
    let reussi = await ouvrirConversation(id)

    return
  }

  }
  ... data-load-older-button, data-edit-message, data-delete-message,
      data-block-user, data-unblock-user, data-pick-attachment,
      data-remove-attachment, data-cancel-edit ...
})

Les erreurs sous les champs

function viderLesErreurs(formulaire) {
  formulaire.querySelectorAll('.kc-erreur-champ').forEach(function (message) { message.remove() })
  formulaire.querySelectorAll('[aria-invalid="true"]').forEach(function (champ) {
    champ.classList.remove('border-danger')
    champ.classList.add('border-line-strong')
    champ.removeAttribute('aria-invalid')
  })
}

function afficherErreurSurChamp(formulaire, nomDuChamp, message) {
  let champ = formulaire.querySelector('[name="' + nomDuChamp + '"]')
  if (champ === null) { return false }

  champ.classList.remove('border-line-strong')
  champ.classList.add('border-danger')
  champ.setAttribute('aria-invalid', 'true')

  let texte = document.createElement('p')
  texte.className = 'kc-erreur-champ mt-1.5 text-sm text-danger'
  texte.textContent = message
  champ.insertAdjacentElement('afterend', texte)

  champ.addEventListener('input', function () {
    texte.remove()
    champ.classList.remove('border-danger')
    champ.classList.add('border-line-strong')
    champ.removeAttribute('aria-invalid')
  }, { once: true })

  return true
}
  • On retrouve le champ par son nom (name="password"), celui que le serveur renvoie dans errors[].field. Si le champ n'existe pas dans ce formulaire, la fonction renvoie false, et l'appelant affichera le message en notification.
  • Une bordure rouge et un texte rouge juste sous le champ (insertAdjacentElement('afterend', …)). aria-invalid="true" signale l'erreur aux lecteurs d'écran.
  • { once: true } : l'écouteur ne sert qu'une fois, puis se retire tout seul. Dès que l'utilisateur corrige le champ, l'erreur disparaît.

11. loader.js : le chargeur plein écran

Le chargeur (components/loader.edge : un anneau « liquide » animé et le logo au centre) est visible dès le départ, et loader.js décide quand le cacher et le remontrer. Si JavaScript est désactivé, un <noscript><style>#kc-loader { display: none; }</style></noscript> le cache, sinon la page resterait bloquée derrière lui.

var chargeur = document.getElementById('kc-loader')
var nombreRequetesEnCours = 0
var minuteurRequete = null

function afficherChargeur() {
  if (chargeur === null) { return }
  chargeur.classList.remove('opacity-0', 'invisible')
}
function masquerChargeur() {
  if (chargeur === null) { return }
  chargeur.classList.add('opacity-0', 'invisible')
}

On l'affiche ou on le cache avec des classes. opacity-0 donne un fondu grâce à la transition CSS, et invisible l'empêche de bloquer les clics une fois caché.

Les quatre situations

// 1. Chargement de la page

  • pageshow avec persisted : quand on revient avec le bouton Retour, le navigateur peut ressortir la page de sa mémoire, telle qu'on l'avait quittée (le « bfcache »). Un formulaire classique va charger une nouvelle page, donc on montre le chargeur. Sauf :

  • si un autre script a déjà annulé l'envoi (defaultPrevented). C'est le cas des formulaires data-ajax, de la saisie des messages et de la recherche d'utilisateurs, qui ne quittent pas la page ;
  • si le formulaire porte data-no-loader.
// 3. Clic sur un lien vers une autre page du site

  if (toucheSpeciale || autreSite || memePageAvecAncre) { return }

})

Le chargeur ne s'affiche que si le clic va vraiment remplacer la page actuelle. Toutes les exceptions sont nommées par une variable, ce qui rend la règle lisible :

  • un autre script a pris le clic en charge (les liens de conversation de message.js) ;
  • nouvel onglet, téléchargement, ou data-no-loader ;
  • Ctrl / Cmd / Maj + clic, ou clic du milieu (button !== 0) : ils ouvrent un nouvel onglet ou une nouvelle fenêtre, et la page actuelle reste ;
  • un lien vers un autre site ;
  • une ancre sur la même page (#section) : on défile, on ne change pas de page.

Sans ces exceptions, le chargeur resterait affiché pour toujours sur une page qui n'est jamais partie.

// 4. Requêtes vers le backend avec fetch
var fetchOriginal = window.fetch

window.fetch = function (adresse, options) {
  if (options && options.noLoader === true) {
    return fetchOriginal.apply(window, arguments)
  }
  if (document.body.dataset.loaderFetch === 'off') {
    return fetchOriginal.apply(window, arguments)
  }

  nombreRequetesEnCours = nombreRequetesEnCours + 1
  if (nombreRequetesEnCours === 1) {
    minuteurRequete = setTimeout(afficherChargeur, 250)
  }

  function requeteTerminee() {
    nombreRequetesEnCours = nombreRequetesEnCours - 1
    if (nombreRequetesEnCours === 0) {
      clearTimeout(minuteurRequete)
      masquerChargeur()
    }
  }

  return fetchOriginal.apply(window, arguments).finally(requeteTerminee)
}
  • On remplace la fonction fetch du navigateur par la nôtre (c'est du « monkey patching »). Le commentaire l'explique : toutes les requêtes du site passent ainsi par ici, sans modifier chaque fichier. On garde l'originale dans fetchOriginal et on l'appelle à la fin.
  • fetchOriginal.apply(window, arguments) appelle la vraie fonction avec exactement les mêmes arguments. arguments contient tout ce qui a été passé, et apply fixe this à window, ce que fetch exige.
  • Deux façons de désactiver le chargeur :
    • pour une requête précise : fetch(url, { noLoader: true }), utilisé par realtime.js pour les compteurs ;
    • pour toute une page : <body data-loader-fetch="off">, posé par message.js et users.js.
  • Le compteur de requêtes : si trois requêtes partent en même temps, le chargeur ne doit disparaître qu'à la fin de la dernière. On compte celles en cours, et on ne cache qu'au retour à 0.
  • 250 ms d'attente avant d'afficher : une requête rapide (50 ms) ne fait pas clignoter l'écran. Si elle se termine avant, clearTimeout annule l'affichage.
  • .finally(...) s'exécute que la requête réussisse ou échoue (panne réseau comprise). Le compteur ne reste jamais bloqué. finally renvoie la même réponse, donc l'appelant reçoit exactement ce qu'il aurait reçu sans nous.
  • var au lieu de let dans ce fichier : c'est l'ancienne façon de déclarer une variable, et l'effet est le même ici.

12. Ce qui a été remarqué

Ce qui est bien fait, à mettre en avant :

• Un seul fichier de messagerie pour deux pages, grâce aux adresses lues dans le HTML.

• Un historique propre (pushState / replaceState / popstate) : le bouton Retour du téléphone fait ce qu'on attend.

• La délégation d'événements partout, et des attributs data-… plutôt que des classes CSS pour relier HTML et JavaScript.

• Un seul système pour tous les formulaires data-ajax, configurable dans le HTML, avec une gestion claire de chaque code d'erreur.

• Le respect de l'accessibilité (role="alert", aria-live, aria-invalid), et textContent pour tout texte venu du serveur.

• Un chargeur qui ne clignote pas (250 ms, compteur de requêtes) et ne reste jamais bloqué (pageshow, finally, exceptions des liens).

1. fichierJoint est utilisé avant d'être déclaré. ouvrirConversation (ligne 117) écrit fichierJoint = null, alors que let fichierJoint n'est déclaré qu'à la ligne 185. Ça fonctionne, car ouvrirConversation n'est jamais appelée avant que tout le fichier soit exécuté. Mais si un jour elle était appelée au chargement, on aurait l'erreur « Cannot access 'fichierJoint' before initialization ». Il suffit de déplacer la déclaration en haut du fichier, avec les autres variables. La ligne 117 est aussi mal indentée.

2. Le double envoi reste possible pendant une redirection. Après un succès avec data-redirect, le bloc finally réactive le bouton pendant les 1,5 s avant le changement de page. Un second clic renverrait le formulaire (par exemple une deuxième inscription, ce qui renverrait un e-mail). On pourrait laisser le bouton désactivé quand une redirection est prévue.

3. confirm() pour les suppressions et le blocage. C'est simple et ça fonctionne, mais l'apparence de ces boîtes dépend du navigateur, et elles ne sont pas en accord avec le reste du design. Les fenêtres <dialog> déjà utilisées dans les paramètres pourraient les remplacer.

4. Remplacer window.fetch pour tout le site est pratique, mais invisible pour qui lit un autre fichier : on peut chercher longtemps pourquoi un chargeur apparaît. Le commentaire en tête de loader.js l'explique bien. Les options noLoader et data-loader-fetch limitent les surprises.

5. Le temps réel recharge la page après une reconnexion (déjà signalé dans le fichier sur le temps réel). Un fichier choisi mais pas encore envoyé, ou un mode modification ouvert, sera perdu si le texte du champ était vide.
